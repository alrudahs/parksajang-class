# 박사장 클라쓰 · VS Code(Claude Code) 랜딩 제작·배포 프롬프트

> 한 단계씩 입력하고, 결과를 확인한 뒤 다음 단계로 넘어간다.
> 모든 단계가 끝나면 captures 폴더에 단계별 화면 캡처가 쌓여서 발표 자료(구현 화면)로 바로 쓸 수 있다.

## 시작 전 준비 (직접 하기)

1. VS Code → 파일 → 폴더 열기 → 바탕화면 PARKSAJANG-CLASS
2. Claude Code 패널 열기
3. GitHub, Vercel 계정 준비 (Vercel은 GitHub로 가입하면 편함)
4. VS Code 확장 Live Server 설치 (미리보기용)
5. Node.js 설치 확인 (캡처 도구 Playwright 실행에 필요) — 터미널에 `node -v` 입력해서 버전이 나오면 OK

## 캡처 규칙 (모든 단계 공통)

- 폴더: `captures/`
- 파일 이름: `단계번호-페이지이름-mobile.png`, `단계번호-페이지이름-desktop.png`
  예) `02-index-mobile.png`, `03-checkout-desktop.png`
- 크기: 모바일 375×812, 데스크톱 1440×900, 페이지 전체(full page)
- 단계가 끝날 때마다 그 단계에서 새로 만들거나 바뀐 페이지를 캡처
- 캡처 목록은 `captures/README.md`에 단계별로 한 줄씩 기록 (날짜, 파일 이름, 무엇을 보여주는 화면인지)

## 1단계 · 프로젝트 계획 + 캡처 도구 준비

```
docs/landing-content.md, docs/banner-copy.md, docs/wireframe.png, docs/service-paths.png 를 먼저 꼼꼼히 읽어줘.
이걸 바탕으로 "박사장 클라쓰" 랜딩페이지와 서비스 경로(A·B·C)를 만들 거야.

조건:
- 빌드 도구 없이 HTML + CSS + 바닐라 JS로만 만든다 (Vercel에 그대로 배포할 수 있게)
- 모바일 우선 (375px 기준), PC에서도 깨지지 않게
- 문구·가격·숫자는 docs/landing-content.md 그대로 쓰고, 임의로 바꾸거나 과장하지 않는다
- 결제는 실제로 일어나지 않는 데모

지금은 화면 코드를 짜지 말고,
1) 만들 페이지 목록과 폴더 구조를 제안하고
2) 프로젝트 규칙을 정리한 CLAUDE.md 파일을 만들어줘
   (브랜드 컬러, 폰트, 톤, 쓰지 않을 말, 이벤트 이름 규칙, 데모 결제 원칙, 캡처 규칙 포함)
3) 진행 과정 캡처를 위해 captures 폴더를 만들고, Playwright로 페이지를 캡처하는 스크립트 scripts/capture.js 를 만들어줘
   - 사용법: node scripts/capture.js 단계번호 페이지1.html 페이지2.html ...
   - 페이지마다 모바일(375×812)과 데스크톱(1440×900) 전체 화면을 captures/단계번호-페이지이름-mobile.png / -desktop.png 로 저장
   - 로컬 파일을 바로 열어서 캡처 (서버 없이)
   - 캡처할 때마다 captures/README.md 에 날짜, 파일 이름, 한 줄 설명을 추가
   - 필요한 설치(npm init, playwright 설치, 크로미움 설치)는 명령어와 이유를 한 줄씩 설명하면서 진행
4) CLAUDE.md 에 "각 단계가 끝나면 바뀐 페이지를 scripts/capture.js 로 캡처하고 결과 파일 목록을 알려준다"는 규칙도 넣어줘
5) captures 와 node_modules 는 .gitignore 에 넣어서 GitHub에는 올라가지 않게 해줘
```

✅ 확인: captures 폴더와 scripts/capture.js 가 생겼는지, 페이지 목록에 랜딩·경로 A·B·C·설문이 모두 있는지

## 3단계 · 경로 A (체크리스트 신청 → 템플릿 구매)

```
docs/landing-content.md 의 "경로 A" 대로 페이지를 만들어줘.

랜딩 → 체크리스트 신청 폼 → 신청 완료·다운로드 → 운영 템플릿 상세 → 주문서 → 구매 완료

- 신청 폼은 이름 + 카카오톡 아이디 또는 이메일, 2칸만. 마케팅 수신 동의 체크박스와
  "광고 폭탄 없음 · 언제든 수신 거부" 안내 포함. 빈칸이면 제출이 안 되게
- 신청 완료 화면: 체크리스트 다운로드 버튼(지금은 임시 PDF 링크 자리) +
  템플릿 샘플 미리보기 + "3일 한정 19,900원 → 14,900원" 배너 + 템플릿 보러 가기 버튼
- 주문서에서 할인 적용 여부가 보이게, 결제하기 버튼은 데모로 바로 구매 완료로 이동
- 구매 완료 화면에 임의 주문번호와 "무료 Zoom 라이브 우선 초대" 안내
- 입력값은 저장하지 말고 다음 화면으로 넘기는 데만 써줘 (실제 개인정보 저장 없음)
- 모든 페이지는 css/style.css 를 같이 써서 디자인을 통일해줘

다 만들면 경로 A 페이지 5개를 node scripts/capture.js 03 ... 으로 캡처하고,
캡처 파일을 경로 순서대로 정리한 목록을 captures/README.md 에 "경로 A 시연 순서"로 따로 적어줘.
```

✅ 확인: 랜딩 CTA부터 구매 완료까지 끝까지 눌러보기 (발표 시연 경로)

## 4단계 · 경로 B (운영 셀프 진단)

```
docs/landing-content.md 의 "경로 B" 대로 셀프 진단 페이지를 만들어줘.

셀프 진단 시작 → 10문항 → 결과 미리보기(점수만) → 연락처 등록 → 전체 결과 + 코칭 안내

- 10문항은 한 화면에 1문항씩, 예/아니오 버튼, 위에 진행 바(1/10)
- 점수 구간: 8~10 상 / 5~7 중 / 0~4 하
- 결과 미리보기에서는 점수와 구간만 보여주고, 항목별 개선 팁은 연락처 등록 후에 보여줘
- 전체 결과: '아니오'라고 답한 문항마다 짧은 개선 팁 1줄씩
  하 구간이면 프리미엄 1주 집중 현장 컨설팅, 중 구간이면 운영 템플릿, 상 구간이면 무료 Zoom 라이브를 안내
- 개선 팁은 박사장 톤(든든하고 솔직하고 현실적)으로 쓰고, 매출 보장 같은 표현은 쓰지 마

다 만들면 캡처해줘 (단계번호 04).
- 진단 시작 화면, 문항 화면(1번), 결과 미리보기, 전체 결과를 각각 캡처
- 전체 결과는 상·중·하 세 구간이 다 보이게 테스트용 주소(예: ?demo=high / mid / low)를 만들어서 3장 캡처
```

✅ 확인: 상·중·하 결과가 다르게 나오는지

## 6단계 · AEO 기술 설정 (검색·AI 노출)

```
docs/landing-content.md 의 "6. AEO 기술 설정"을 적용해줘.

- index.html 에 페이지 제목(title)과 설명(meta description)을 문서 그대로 넣기
- 공유용 og:title, og:description, og:image(images/og.png 자리) 추가
- FAQ 섹션 5개 질문·답변으로 FAQPage 구조화 데이터(JSON-LD)
- Organization 구조화 데이터(JSON-LD): 이름, 한 줄 소개, 대표 박미경, 채널 URL 자리
- robots.txt (모든 크롤러 허용) 와 sitemap.xml 생성
  (배포 주소는 아직 없으니 https://YOUR-DOMAIN 으로 두고, 나중에 한 번에 바꿀 수 있게 알려줘)
- 하위 페이지들도 각각 알맞은 title 과 description 넣기

다 만들면
- 화면은 바뀐 게 없으니 캡처 대신, index.html 의 <head> 부분과 JSON-LD 코드를
  captures/06-aeo-head.txt 로 저장하고 README.md 에 기록해줘 (발표 때 근거로 보여줄 용도)
```

✅ 확인: 배포 후 Google 리치 결과 테스트로 FAQ가 잡히는지 (10단계 뒤)

## 7단계 · GTM 설치 자리 + GA4 이벤트

```
모든 페이지에 Google Tag Manager 설치 코드를 넣어줘.
GTM 컨테이너 ID는 아직 없으니 GTM-XXXXXXX 로 두고, 나중에 한 곳만 바꾸면 되도록 js/config.js 로 분리해줘.

docs/landing-content.md 의 "7. GA4 이벤트" 표에 있는 이벤트를
알맞은 버튼·폼·화면에서 window.dataLayer.push 로 보내줘.
- 이벤트 이름과 함께 보낼 정보 이름은 표와 똑같이
- js/tracking.js 한 파일에 모아서 관리
- 개발 중 확인할 수 있게, 주소 뒤에 ?debug=1 이 붙으면 이벤트가 나갈 때마다 콘솔에 찍히고,
  화면 오른쪽 아래에 작은 이벤트 로그 상자도 보이게 해줘 (캡처로 확인하기 위해)

마지막에 "어떤 페이지의 어떤 행동에서 어떤 이벤트가 나가는지" 표를 docs/event-map.md 로 저장해줘.

다 만들면 캡처해줘 (단계번호 07).
- ?debug=1 을 붙인 상태로 경로 A를 자동으로 따라가면서
  (CTA 클릭 → 신청 → 다운로드 → 템플릿 상세 → 주문서 → 구매 완료)
  각 화면에서 이벤트 로그 상자가 보이게 캡처
```

✅ 확인: 07번 캡처마다 이벤트 이름이 순서대로 찍혀 있는지
